System Architecture

The CHF lead management platform connects four core systems in a bidirectional data pipeline. Leads enter via HubSpot, are routed to RingCX dialing campaigns with age-based prioritisation, and call recordings are backed up to Google Drive via a GCE VM.

📖

HubSpot

CRM — lead entry, contact properties, call engagements, workflows

📞

RingCX

Dialer — campaigns, agents, call recordings, dispositions

⚡

Supabase

Data hub — edge functions, cron jobs, database, auth tokens

📁

Google Drive

Backup — call recordings via GCE VM + rclone SFTP

Data Flow Summary

Lead Created in HubSpot
Web form submission or manual entry. HubSpot workflow fires on lead_date property change.
Webhook → Supabase Edge Function
HubSpot sends campaign IDs (hotCampaignId, newCampaignId, oldCampaignId) to ringcx-lead-ingest.
Tier Classification & Campaign Injection
Lead is classified HOT (≤72h old) or NEW (>72h), pushed to the appropriate RingCX campaign via Lead Loader API.
Agent Dials & Records Disposition
RingCX agent calls the lead. On completion, a disposition webhook fires back to Supabase.
HubSpot Call Engagement Created
ringcx-disposition-webhook creates a call record in HubSpot associated with the contact.
Recording Backed Up to Google Drive
GCE VM downloads from RingCX → uploads to Drive via rclone → recording-to-storage syncs URL to HubSpot.

Lead Entry Points

📝 Web Form Submissions

Captured by hubspot-form-submission edge function. Handles 7 disposition types (Book Water Test, Call Back, Not Interested, etc.). Searches for existing contact by email/phone; creates new if not found.

⚙ HubSpot Workflows

Property-change workflows fire webhooks when campaign IDs are set on a contact. These trigger the lead loader functions to push leads into RingCX campaigns.

🔥 Lead Ingest (Tier Router)

The ringcx-lead-ingest function receives HOT/NEW/OLD campaign IDs from HubSpot and classifies the lead based on age. Stores routing data in ringcx_lead_routing table.

HOT → NEW → OLD Waterfall

Leads age through three tiers based on the time since their lead_date. Each tier maps to a different set of RingCX campaigns with different dial priorities.

🔥 HOT

0–72 hours after lead_date
IMMEDIATE Priority
72 hours

⭐ NEW

72 hours – 90 days
NORMAL Priority
90 days

🕒 OLD

90+ days
NORMAL Priority

Aging Cron Jobs

🔥 HOT → NEW Aging

Function: ringcx-lead-aging-hot

Schedule: Every 2 hours

Logic: Finds HOT leads where lead_date ≤ NOW() - 72 hours. Uses RingCX MOVE_TO_CAMPAIGN API to move the lead from the HOT campaign to the NEW campaign. Updates ringcx_lead_routing table and notifies Google Chat.

⭐ NEW → OLD Aging

Function: ringcx-lead-aging-new

Schedule: Daily at 9 PM Perth time

Logic: Finds NEW leads where lead_date ≤ NOW() - 90 days. Moves from NEW campaign to OLD campaign. Updates routing table and notifies Google Chat.

Dial Priority Logic

PriorityConditionDescription
IMMEDIATE Lead created today AND reconversion lead_date = today, but createdate is earlier (previously existed)
IMMEDIATE Lead created today AND re-contacted lead_date = today and num_contacted > 1
NORMAL All other leads Aged leads, first-time contacts, standard queue order

Lead Loader Workflow

HubSpot Property Change Triggers Webhook
Workflow detects campaign ID set on contact → sends webhook payload with contact ID and campaign IDs.
Deduplication Check
hasRecentFailure() checks for duplicate attempts within a 60-minute window.
Fetch Contact & Format Phones
Gets contact from HubSpot API. Converts phone numbers to E.164 format (+61XXXXXXXXX).
Determine Dial Priority
IMMEDIATE for reconversions and re-contacts created today. NORMAL for everything else.
Push to RingCX Lead Loader API
Sends lead with externId, leadPhone, auxPhone1/auxPhone2, firstName, lastName, and campaign-specific timezone.
Search & Writeback
Searches RingCX for the lead (retries with 2s delay if not indexed yet). Writes the RingCX lead ID back to HubSpot contact property.
Log to lead_loads Table
Records the load event with contact snapshot, campaign type, priority, and reason for reporting.

Dispositions & Webhooks

Disposition Webhook Flow

When a RingCX agent completes a call, the platform sends a POST request to ringcx-disposition-webhook with template variables.

Validate Required Fields
Checks for extern_id (HubSpot contact ID), call_id (UII), agent_id. Skips unresolved template variables.
Map RingCX Disposition → HubSpot GUID
Converts agent disposition text to HubSpot call disposition GUID for standardised reporting.
Create HubSpot Call Engagement
Creates an hs_calls object with title, duration, direction, disposition, and associates it to the contact (type 194).
Store in call_recordings
Inserts record with backup_status = pending and the pre-signed recording URL for later backup.
Agent Mapping & Owner Assignment
Looks up agent_mappings table to set HubSpot call owner. If disposition is "Not Interested", assigns to CHF Promotions owner.

Recording Backup Pipeline

Call recordings flow from RingCX through a GCE VM to Google Drive, then the storage URL is synced back to HubSpot.

Agent Completes Call (RingCX)
Call is recorded. Pre-signed recording URL is included in the disposition webhook payload. URL expires in ~2 hours.
Disposition Webhook → call_recordings
Recording URL stored in ringcx_recording_url column with backup_status = pending.
GCE VM Downloads & Uploads
ringcx-sftp-backup VM (35.189.5.13, e2-micro, australia-southeast1-b) downloads from RingCX URL and uploads to Google Drive via rclone SFTP. Updates storage_url in database.
recording-to-storage Cron (Every 5 min)
Finds recordings with a storage_url but no hubspot_updated_at. PATCHes the HubSpot call engagement with hs_call_recording_url.
Recording Playable in HubSpot
Call engagement now links to the permanent Google Drive URL. Playable inline in HubSpot and the CHF queue dashboard.

Token & Auth Management

RingCentral OAuth Flow

Manual: ringcentral-auth-init
Redirects to RingCentral OAuth endpoint with PKCE challenge. User logs in and authorises.
ringcentral-auth-callback
Exchanges authorisation code for access + refresh tokens. Stores in ringcentral_auth table.
Cron: ringcentral-token-refresh (Every 30 min)
Uses advisory lock to prevent race conditions. Exchanges single-use refresh token for new token pair.
Token Available for All Functions
Lead loaders and disposition webhook read the current access token from the ringcentral_auth table.
Single-Use Refresh Tokens RingCentral refresh tokens can only be used once. If two systems attempt to refresh the same token simultaneously, the second will fail with OAU-210. The cron job is the sole mechanism for refreshing tokens — no just-in-time refresh to prevent race conditions.

RingCX Token Exchange

Some RingCX APIs require a separate JWT token. The exchange flow:

  1. Get RC access token from database
  2. POST to https://ringcx.ringcentral.com/api/auth/login/rc/accesstoken
  3. Body: rcAccessToken={token}&rcTokenType=Bearer (form-urlencoded)
  4. Returns RingCX JWT (expires ~5 minutes)

Supabase Service Role Key

Key Format Issue The auto-injected SUPABASE_SERVICE_ROLE_KEY uses a new sb_secret_* format (41 chars) that is incompatible with supabase-js v2. All edge functions use a custom env var SB_SERVICE_ROLE_KEY that stores the legacy JWT-format key (219 chars).

Database Schema

Core Supabase Postgres tables powering the system:

🔒 ringcentral_auth

Single row. Stores RC OAuth credentials: rc_access_token, rc_refresh_token, expiry timestamps, last refresh error.

📋 ringcx_lead_routing

Tracks each lead's tier journey. One row per contact with HOT/NEW/OLD campaign IDs, current tier, and aging timestamps.

📞 call_recordings

Call metadata + backup status. Tracks recording URL, storage URL, backup status lifecycle, HubSpot sync status.

📈 lead_loads

Reporting table. One row per lead load event with contact snapshot, campaign type, dial priority, and reason.

👥 agent_mappings

Maps RingCX agent IDs to HubSpot owner IDs. Used for call ownership and form submission attribution.

📝 hubspot_form_submissions

Audit trail for all web form submissions. Captures source, submitted_by, disposition, form_data (JSONB).

🗒 ringcx_webhook_logs

Disposition webhook audit trail. Stores full payload, processing status, HubSpot IDs, and error messages.

⚠ error_log

Centralised error tracking. Source (function name), error message, details (JSONB). Indexed by created_at DESC.

Known Issues & Gotchas

OAU-210: Broken Token Chain If the refresh token is used twice (e.g. by two competing systems), the second attempt fails with OAU-210 and the entire chain is broken. Requires manual re-authorisation via ringcentral-auth-init. Historically caused by a legacy Cloudflare Worker cron that has since been deleted.
verify_jwt Deployment Bug Supabase CLI v2.62+ has a bug where the --no-verify-jwt flag is not sent in the deploy API call. After deploying functions that need to accept unauthenticated requests, you must PATCH via the Management API:
PATCH /v1/projects/{ref}/functions/{slug} with {"verify_jwt": false}
Recording URL Expiry RingCX pre-signed recording URLs are valid for approximately 2 hours. The GCE VM must download recordings before expiry. The recordings-backfill cron retries failed downloads, but will fail permanently if the URL has expired.
Lead Indexing Lag Freshly uploaded leads may not be immediately searchable via the RingCX API. The lead loader functions retry with a 2-second delay to account for indexing lag.
Phone Format Sensitivity RingCX requires E.164 format (+61XXXXXXXXX) for Australian numbers. Local formats must be converted before pushing. Leads without valid phone numbers are skipped with a non-retryable 200 response.
